# Stream Studio (iPad) — разбор Camo Studio и план приложения

Личное приложение для стриминга на YouTube с iPad в духе Camo Studio. Разработка — **только в Swift Playgrounds на iPad**, распространение — TestFlight (загрузка в App Store Connect прямо из Playgrounds). Mac нет.

---

## 1. Ограничения iPad + Swift Playgrounds (важно)

| Ограничение | Последствие | Решение |
|---|---|---|
| Playgrounds не умеет **App Extensions** | Нет ReplayKit Broadcast Extension → **нельзя записывать экран самого iPad (другие приложения)**. К камерам это не относится | Камеры по USB‑C (UVC: Sony и др. в режиме «USB Streaming») подхватываются напрямую. Экран — только контент нашего приложения или карта захвата (не приоритет) |
| Только Swift (без C/C++ таргетов) | RNNoise/DeepFilterNet напрямую не подключить | Шумодав: системный Voice Processing + свой спектральный гейт на Swift/Accelerate |
| Нет файлов `.metal` | Шейдеры не собрать заранее | Композитинг на Core Image (Metal под капотом); при необходимости шейдеры компилируются из строки в рантайме |
| Камера в фоне работает только при **multitasking camera access** | Без него камера встаёт при уходе с экрана | Так же, как Camo: активное **PiP‑окно** (видеозвонковый PiP) + Stage Manager держат камеру живой. Проверить первым прототипом |
| Одновременно активен **один аудиовход** | Нельзя микшировать аудиокарту и USB‑микрофон одновременно | Свободное переключение между ними + выбор канала многоканальной карты |
| Нет `usbmuxd` / `adb` на iPad | iPhone по кабелю как в Camo — нельзя | iPhone — по Wi‑Fi. Pixel 7 по кабелю — **режим USB‑веб‑камеры** (UVC) или USB‑модем + наше приложение |
| Глобальные горячие клавиши недоступны | Клавиши работают только когда приложение в фокусе | Клавиатура + **плавающий пульт** (см. §8) + MIDI |

Я (Claude) не могу собрать iOS‑код в своём окружении (Linux) — проверка сборки всегда на iPad. Поэтому код пишем небольшими шагами.

## 2. Как устроена Camo Studio и что берём

| Возможность Camo | Как работает у Camo | На iPad |
|---|---|---|
| Телефон как камера | Приложение на телефоне кодирует H.264/HEVC и шлёт по USB (usbmuxd) или Wi‑Fi | Wi‑Fi (свой протокол) + Android по кабелю как UVC |
| Сцены из слоёв | GPU‑композитинг | Core Image композитор |
| YouTube: вход, автоподхват трансляций | OAuth + YouTube Data API | То же |
| Чат | LiveChat API | То же + PiP‑окно |
| LUT, цветокоррекция | Фильтры | `CIColorCube` + базовые фильтры |
| Запись экрана | Захват экрана Mac | Только карта захвата / контент приложения |
| Выбор микрофона | «Последнее подключённое» — плохо | Явный выбор + переключение |

## 3. Стек

- SwiftUI-приложение (`.swiftpm`), iPadOS 17+ (нужно для внешних USB-камер UVC).
- Камеры: `AVCaptureSession` / `AVCaptureMultiCamSession` (фронт + тыл одновременно), внешние UVC-камеры (`.external`).
- Композитинг: Core Image + `CIContext` на Metal, холст 1920×1080 @ 30 (60 — если потянет по температуре).
- Кодирование: `VideoToolbox` H.264 аппаратно.
- Вывод: **RTMPS** на YouTube. Вариант 1 — [HaishinKit](https://github.com/shogo4405/HaishinKit.swift) как SPM-зависимость (проверить, что собирается в Playgrounds). Вариант 2 — свой минимальный RTMP-клиент на `Network.framework` (~1000 строк).
- Звук: `AVAudioSession` + `AVAudioEngine`.
- Сеть телефонов: `Network.framework` (Bonjour, peer-to-peer Wi‑Fi).
- **iPhone-компаньон**: отдельный проект в Playgrounds → TestFlight.
- **Android-компаньон**: Kotlin; APK собирается **GitHub Actions** (без компьютера), скачивается на телефон.

**Рабочий процесс:** код лежит в этом репозитории → на iPad через приложение **Working Copy** (git-клиент) папка открывается в Swift Playgrounds → сборка/запуск → загрузка в TestFlight из Playgrounds.

## 5. Слои и раскладки

Слои: **Камера**, **Карта захвата**, **Изображение** (подложка/рамка PNG), **Видео** (зацикленный фон), **Текст** (обводка, тень, бегущая строка), **Плашка**, **Алерт**.
Свойства: позиция, масштаб, обрезка, скругление, рамка/тень, прозрачность, зеркало, LUT + сила, яркость/контраст/насыщенность/температура.

Раскладки:
1. Только A
2. Только B
3. A большая + B маленькая
4. B большая + A маленькая
5. A | B рядом
6. Захват + A в углу
7. Только захват

Переходы: срез / плавно (анимация, 300 мс). LUT — импорт `.cube` из «Файлов».

## 6. Горячие клавиши

С аппаратной клавиатурой (Magic Keyboard и т.п.), подсказки показываются на кнопках:
- `⌘1…7` — раскладки
- `⌘S` — поменять A и B местами
- `⌘M` — мьют микрофона
- `⌘⇧L` — старт/стоп эфира (с подтверждением)
- `⌘⇧C` — чат

Дополнительно: MIDI-контроллер / пульт по Bluetooth через CoreMIDI (работает и когда фокус в другом окне Split View — проверить).

## 7. Звук

**Выбор устройства:**
- `AVAudioSession.availableInputs`: встроенный микрофон, USB-аудиокарта, USB-микрофон, Bluetooth.
- Явный выбор (`setPreferredInput`), сохраняем UID, переключение в эфире без остановки.
- Выбор канала многоканальной карты (например, вход 1 моно).
- Устройство отключилось — fallback на запасное, вернуть при подключении.

**Цепочка (каждый блок — вкл/обход):**
1. **Шумодав** — системный Voice Processing (`setVoiceProcessingEnabled`) или свой спектральный гейт (Accelerate/vDSP); плюс доступ к системному режиму «Изоляция голоса».
2. **EQ** — `AVAudioUnitEQ`: HPF 80 Гц + 5 полос, пресеты.
3. **Компрессор** — `AUDynamicsProcessor`.
4. **Лимитер** — `AUPeakLimiter`, потолок −1 dBFS, всегда на мастере.

Индикаторы уровня до/после, мониторинг в наушники.

## 8. YouTube

- OAuth Google через `ASWebAuthenticationSession`, токены в Keychain.
- **Автоподхват:** `liveBroadcasts.list` (upcoming/active) → выбрал трансляцию → привязанный `liveStream` → URL + ключ; нет привязки — создаём и привязываем.
- Старт: шлём поток → ждём `active` → переход в `live`.
- **Чат:** `liveChatMessages.streamList` или `list` с `pollingIntervalMillis`; квота API 10 000 ед/день.
- **Плавающий пульт** (вместо «окошка с временем» у Camo), два режима:
  - **Окно Stage Manager** — полноценный пульт: чат, ● LIVE + таймер, зрители, битрейт/потери, уровень микрофона, кнопки раскладок, мьют, стоп. Перетаскивается, меняет размер, всё нажимается.
  - **PiP**, когда приложение убрано с экрана: тот же чат + статус + таймер, перетаскивается. В PiP нельзя свои кнопки — только системные: «пауза» = мьют микрофона, «‹ ›» = предыдущая/следующая раскладка. PiP заодно держит камеру живой.

## 9. VPN

- RTMPS на **порту 443** (`rtmps://a.rtmps.youtube.com:443/live2`).
- Адаптивный битрейт, тест скорости перед эфиром, индикатор очереди/потерь, автопереподключение.
- iPhone по Wi‑Fi: VPN может резать локальную сеть и Bonjour → в VPN включить «локальная сеть» / split tunneling; запасной вариант — QR-код с IP:порт; **peer-to-peer Wi‑Fi** (AWDL, iPhone↔iPad напрямую, без роутера) — проверить, как ведёт себя с VPN.
- **Android по кабелю (UVC) от VPN не зависит вообще.**
- Учесть: VPN-приложение и наше одновременно — фоновый VPN на iPadOS работает штатно.

## 10. Телефоны как камеры

| | Wi‑Fi | Кабель |
|---|---|---|
| **Android (Pixel 7)** | Своё приложение (CameraX → MediaCodec H.264 → TCP): полный контроль объектива/экспозиции, до 4K | **Вариант 1:** встроенный режим веб-камеры (USB → «Веб-камера», есть «Высокое качество») → iPad видит как обычную UVC-камеру, приложение не нужно. **Вариант 2:** USB-модем (NCM) + наше приложение по проводу — полное качество и управление; проверить, видит ли iPad сеть и не ломает ли это VPN |
| **iPhone** | Своё приложение (AVCapture → VideoToolbox → TCP), Bonjour / QR / peer-to-peer | Нет прямого способа. Вариант: USB-хаб с Ethernet у обоих — фактически сеть |

Протокол: TCP, заголовок (тип, timestamp, длина) + H.264 NAL Annex B; управляющий канал JSON (объектив, разрешение, fps, зум, фокус, экспозиция, ББ, фонарик). Декод — `VTDecompressionSession`.

## 11. Донаты (DonationAlerts)

Браузер-источник как в OBS на iPad дорог (WKWebView не рендерится офскрин в реальном времени), поэтому **нативно**:
- OAuth DonationAlerts + real-time через Centrifugo WebSocket.
- Свои алерты (анимация, текст, звук), **бегущая строка донатов** (текстовый слой), сбор на цель.
- **Озвучка**: `AVSpeechSynthesizer` (русский голос) → буферы прямо в микшер, гарантированно в эфире. Мин. сумма, фильтр мата, очередь, «пропустить».

## 14. Что проверить первым (прототипы)

Устройства: iPad Pro M4, последняя iPadOS, Pixel 7, камеры Sony по USB‑C.

1. Собирается ли HaishinKit в Playgrounds (иначе — свой RTMP).
2. Камера фронт + тыл одновременно на твоём iPad; внешняя USB-камера + встроенная одновременно.
3. Android-телефон в режиме USB-веб-камеры виден iPad.
4. Камера не останавливается в Stage Manager и при активном PiP.
5. Pixel 7 по USB-модему виден iPad как сеть.
