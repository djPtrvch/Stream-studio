# Stream Studio — разбор Camo Studio и план приложения

Личное приложение для стриминга на YouTube в духе Camo Studio: несколько камер (включая телефоны), захват экрана, оверлеи, обработка микрофона, чат, донаты, горячие клавиши. Распространение — TestFlight (macOS + iOS-компаньон), Android-компаньон — APK.

---

## 1. Как устроена Camo Studio (и что берём)

| Возможность Camo | Как работает | Берём? |
|---|---|---|
| Телефон как камера (USB / Wi‑Fi) | Приложение на телефоне кодирует H.264/HEVC аппаратно и шлёт на Mac. По USB для iPhone — через `usbmuxd` (TCP-туннель поверх кабеля), по Wi‑Fi — по локальной сети с Bonjour-обнаружением | **Да**, основа |
| Сцены из слоёв (камера, экран, картинка, текст, видео) | GPU-композитинг в один кадр, слои с позицией/масштабом/обрезкой | **Да** |
| Подключение YouTube, автоподхват трансляций | OAuth Google → YouTube Data API: список запланированных/активных broadcasts, привязка stream key | **Да** |
| Чат в приложении | YouTube LiveChat API | **Да** + отдельное плавающее окно |
| Шаблоны/оверлеи, нижние трети | Готовые пресеты слоёв | Частично (свои пресеты) |
| Коррекция изображения, LUT, размытие фона | Core Image/Metal фильтры, сегментация Vision | LUT + цвет — да, фон — позже |
| Виртуальная камера для Zoom и т.п. | CoreMediaIO Camera Extension | Опционально, позже |
| Выбор микрофона | Берёт последнее подключённое устройство — **плохо** | **Переделываем**: явный выбор по UID |
| Обработка звука | Минимальная | **Делаем полноценную цепочку** |

Чего в Camo нет/слабо и мы добавляем: цепочка обработки микрофона, донаты с озвучкой, горячие клавиши на раскладки камер, нормальная работа через VPN.

## 2. Платформа и стек

- **macOS-приложение** (Apple Silicon, macOS 14+): Swift + SwiftUI.
  - Захват камер: `AVFoundation` (`AVCaptureSession`).
  - Захват экрана/окна + звука системы: `ScreenCaptureKit`.
  - Композитинг: **Metal** (+ Core Image для фильтров/LUT). Холст 1920×1080 @ 30/60.
  - Кодирование: `VideoToolbox` (H.264 аппаратно; HEVC — опционально через Enhanced RTMP).
  - Вывод: **RTMPS** на YouTube (библиотека [HaishinKit](https://github.com/shogo4405/HaishinKit.swift)).
  - Звук: `AVAudioEngine` + Core Audio.
- **iOS-компаньон** (камера): Swift, `AVCaptureSession` → `VideoToolbox` → сеть. Через TestFlight.
- **Android-компаньон** (камера): Kotlin, CameraX/Camera2 → `MediaCodec` (H.264) → сеть. APK вручную.

> ⚠️ **TestFlight на macOS требует App Sandbox.** Это осложняет USB-подключение телефонов (доступ к сокету `usbmuxd`, запуск `adb`). Внутреннее тестирование TestFlight не проходит App Review, так что temporary-exception entitlements скорее всего пройдут, но это риск.
> **Рекомендация:** для личного использования проще собирать Mac-приложение как **Developer ID + нотаризация** (dmg, без песочницы). TestFlight оставить для iOS-компаньона. Архитектуру делаем так, чтобы работало в обоих вариантах.

## 3. Архитектура

```

 ─────────                         ──────────────────            ─────
 Камера A (USB/встроенная) ─┐
 Камера B (iPhone USB/WiFi) ─┤      Сцена = стек слоёв     ┌─> Превью в окне
 Камера C (Android)         ─┼─> LUT/цвет ─> позиция/масштаб ─┼─> VideoToolbox H.264 ─┐
 Экран (ScreenCaptureKit)   ─┤      + переходы              └─> Запись в файл       │
 Картинка/видео/текст       ─┤                                                       ├─> RTMPS → YouTube
 Браузер-источник (алерты)  ─┘                                                       │
                                                                                     │
 Микрофон (выбранный UID) ─> NR ─> EQ ─> Комп ─> Лимитер ─┐                          │
 Звук системы (SCK)  ────────────────────────────────────┼─> Микшер ─> AAC 48k ─────┘
```

Модули (Swift Packages внутри проекта):
- `Capture` — камеры, экран, телефоны.
- `Compositor` — сцены, слои, фильтры, переходы.
- `AudioEngine` — устройства, цепочка эффектов, микшер, индикаторы.
- `Output` — энкодер, RTMPS, запись.
- `YouTube` — OAuth, broadcasts, chat.
- `Alerts` — DonationAlerts, очередь алертов, TTS.
- `PhoneLink` — протокол телефон↔Mac, обнаружение, USB.
- `Hotkeys` — глобальные горячие клавиши.

## 4. Слои и сцены

Типы слоёв: **Камера**, **Экран/окно**, **Изображение** (подложка, рамка, PNG с альфой), **Видео** (зацикленный фон), **Текст** (шрифт, обводка, тень, бегущая строка), **Браузер** (URL виджета, офскрин `WKWebView`), **Цветная плашка**.

Свойства слоя: позиция, масштаб, поворот, обрезка, скругление, тень/рамка, прозрачность, видимость, фильтры (LUT, яркость/контраст/насыщенность/температура, резкость), зеркало.

Сцена = набор слоёв + **раскладка**. Готовые раскладки:
1. Только камера A
2. Только камера B
3. A большая + B маленькая (PiP)
4. B большая + A маленькая (PiP)
5. A и B рядом (50/50)
6. Экран + камера A в углу
7. Только экран

Переходы между раскладками: «срез» и «плавно» (анимация позиции/масштаба слоёв, 300 мс).

**LUT:** импорт `.cube` (17/33/65), применение через `CIColorCubeWithColorSpace` или Metal 3D-текстуру; на каждый слой камеры — свой LUT + сила (0–100%).

## 5. Горячие клавиши

- Глобальные (работают, когда приложение свёрнуто): Carbon `RegisterEventHotKey` — не требует разрешения Accessibility.
- По умолчанию (переназначаемые):
  - `⌃⌥1…7` — раскладки из списка выше
  - `⌃⌥S` — поменять A и B местами (большая ↔ маленькая)
  - `⌃⌥M` — мьют микрофона
  - `⌃⌥L` — старт/стоп эфира (с подтверждением)
  - `⌃⌥C` — показать/скрыть окно чата
- Подсказки с клавишами видны прямо на кнопках раскладок в интерфейсе.
- Позже: Stream Deck / MIDI.

## 6. Звук

**Выбор устройства (исправляем проблему Camo):**
- Список всех входов через Core Audio (`kAudioHardwarePropertyDevices`), сохраняем **UID** устройства, а не «последнее подключённое».
- Выпадающий список + горячее переключение без остановки эфира (короткий кроссфейд).
- Выбор канала(ов) для многоканальных аудиокарт (например, вход 1 моно с 4-канальной карты).
- Если выбранное устройство отключилось — fallback на заданный запасной, вернуться при повторном подключении.

**Цепочка на микрофон (каждый блок включается/обходится):**
1. **Шумоподавление** — RNNoise (лёгкий, BSD) или DeepFilterNet (лучше, тяжелее). Ползунок силы.
2. **Gate** (опционально).
3. **Эквалайзер** — `AVAudioUnitEQ`, 5 полос + HPF 80 Гц; пресеты «Голос», «Подкаст».
4. **Компрессор** — `AUDynamicsProcessor` (порог, ratio, атака, релиз, makeup).
5. **Лимитер** — `AUPeakLimiter`, потолок −1 dBFS, **всегда включён на мастере**.

Индикаторы уровня (peak/RMS) на входе и выходе, мониторинг в наушники.

## 7. YouTube

- **Вход:** OAuth 2.0 Google (desktop flow через `ASWebAuthenticationSession`), скоупы `youtube` / `youtube.force-ssl`. Токены — в Keychain.
- **Автоподхват трансляций:** `liveBroadcasts.list` (`broadcastStatus=upcoming|active`) → список в интерфейсе. Выбрал трансляцию → берём привязанный `liveStream` (`liveStreams.list`) → ingestion URL + ключ. Нет привязанного потока — создаём и привязываем (`liveBroadcasts.bind`).
- Опционально: создание трансляции прямо из приложения (название, описание, превью, приватность).
- **Старт:** начинаем слать поток → ждём `streamStatus=active` → `transition` в `live` (или включённый autoStart).
- **Чат:** `liveChatMessages.streamList` (серверный стрим) или `liveChatMessages.list` с соблюдением `pollingIntervalMillis`. Учитываем квоту API (10 000 ед/день по умолчанию).
- **Отдельное окно чата:** `NSPanel` поверх всех окон, полупрозрачный, всегда на всех рабочих столах. Автоматически появляется, когда главное окно свёрнуто/скрыто, прячется при возврате. Можно ответить в чат.

## 8. VPN

YouTube доступен только через VPN, поэтому:
- **RTMPS на порту 443** (`rtmps://a.rtmps.youtube.com:443/live2`) — меньше шансов, что заблокировано/зарезано, чем RTMP:1935.
- **Адаптивный битрейт** с запасом: VPN снижает пропускную способность. Тест скорости до ingest перед эфиром, индикатор «потеря кадров/очередь».
- **Автопереподключение** при обрыве VPN (с буфером несколько секунд, YouTube держит трансляцию ~ до минуты без данных).
- **Телефоны по Wi‑Fi через VPN:** многие VPN блокируют локальную сеть или ломают Bonjour. Решения:
  - Включить в VPN «разрешить локальную сеть» / split tunneling для LAN.
  - Резервное подключение по **QR-коду с IP:порт** вместо Bonjour.
  - **USB-подключение вообще не зависит от VPN** — рекомендуется как основное.
- OAuth и API YouTube идут через системный VPN без доп. настроек.

## 9. Телефоны как камеры

**Протокол** (один на все платформы): TCP, кадры с заголовком (тип, timestamp, длина) + H.264/HEVC NAL-юниты Annex B; управляющий канал JSON (выбор камеры, разрешение, fps, зум, фокус, экспозиция, баланс белого, фонарик). Декодирование на Mac — `VTDecompressionSession` (аппаратно). Задержка цель: <100 мс по USB, <200 мс по Wi‑Fi.

| | Wi‑Fi | Провод |
|---|---|---|
| **iPhone** | Bonjour (`_streamstudio._tcp`) или QR | `usbmuxd`: Mac подключается к порту на телефоне через туннель (как Camo/peertalk). Без режима разработчика |
| **Android** | Bonjour/NSD или QR | `adb forward` (встроенный adb, нужна «Отладка по USB») — самый надёжный вариант. Альтернатива — USB-модем (RNDIS) |

Приложение на телефоне: выбор объектива (широкий/ультраширокий/фронтальная), 1080p/4K, 30/60, блокировка экспозиции/фокуса, экран гаснет во время трансляции, индикатор температуры/батареи.

## 10. Донаты (DonationAlerts)

Два способа, делаем оба:
1. **Браузер-источник** (как в OBS): вставляешь URL виджета DonationAlerts (алерты, сборы, последние донаты) → рендер через офскрин `WKWebView` в слой. Быстро, вся настройка — на стороне DA. Звук виджета захватываем через ScreenCaptureKit (аудио собственного приложения) — нужно проверить на прототипе.
2. **Нативно через API DonationAlerts** (OAuth + real-time через Centrifugo WebSocket): свои алерты (анимация + текст + звук), **бегущая строка донатов** текстовым слоем, **озвучка** через TTS (`AVSpeechSynthesizer` с русским голосом, или внешний TTS) — звук идёт прямо в микшер, гарантированно попадает в эфир. Фильтр мата, мин. сумма для озвучки, очередь алертов, кнопка «пропустить».
